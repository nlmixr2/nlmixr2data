# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when
working with code in this repository.

## Overview

**nlmixr2data** is a data-only R package that collects the example
datasets used by the nlmixr2 project (`nlmixr2`, `rxode2`) in one place.
It has no exported functions, no compiled code, and no package
dependencies beyond `R (>= 2.10)`. `LazyData: true`, so every dataset is
available after `library(nlmixr2data)` (e.g. `head(theo_sd)`).

## Build and Development Commands

### Install/Build
```r
devtools::install()
# Or from the shell
R CMD INSTALL .
```

### Document
```r
devtools::document()
```
Regenerates `man/*.Rd` (and the empty `NAMESPACE`) from the roxygen
blocks in `R/`. Roxygen uses markdown (`Roxygen: list(markdown = TRUE)`).

### R CMD Check
```r
devtools::check()
# Or: R CMD build . && R CMD check nlmixr2data_*.tar.gz --as-cran
```
There is no `tests/` directory; `R CMD check` (documentation vs. data
consistency, data loading) is the test suite.

### README
`README.md` is generated from `README.Rmd`; edit the `.Rmd` and re-knit
(`devtools::build_readme()`). Never edit `README.md` by hand.

## Architecture

- `data/*.rda` -- one serialized data frame per dataset. These are the
  shipped data; there is no `data-raw/` directory, so the scripts that
  created them are not in this repository.
- `R/*.R` -- roxygen documentation only. Each file documents one dataset
  with a roxygen block ending in the quoted object name (e.g.
  `"theo_sd"`). File names are mostly `data_<name>.R` or `<name>.R`.
- `man/*.Rd` -- generated by roxygen2; do not edit by hand.
- `inst/CITATION` -- package citation (cites nlmixr).
- `_pkgdown.yml`, `pkgdown/` -- pkgdown site config
  (https://nlmixr2.github.io/nlmixr2data/).

### Adding or changing a dataset

1. Save the object to `data/<name>.rda` (e.g.
   `usethis::use_data(<name>, overwrite = TRUE)`); the `.rda` file name
   must match the object name.
2. Add/update `R/<name>.R` (or `R/data_<name>.R`) with a roxygen block:
   title, description, `@format` with a `\describe{}` listing every
   column, `@source` and/or `@author`, and `@family nlmixr2 datasets`,
   followed by the quoted object name.
3. Run `devtools::document()` and `devtools::check()`.
4. Add a bullet to `NEWS.md`.

Downstream packages in the nlmixr2 ecosystem (nlmixr2, rxode2, ...) use
these datasets in examples, vignettes, and tests. Do not rename, remove,
or change the columns/values of an existing dataset without explicit
user permission -- add a new dataset instead.

## Code and Documentation Style

- Roxygen comments in `R/` use both `#'` and `##'`; match the style
  already used in the file being edited.
- Keep `@format` row/column counts accurate for the shipped data.
- `NEWS.md` is organized per version (`# nlmixr2data X.Y.Z`) with
  past-tense bullets.
- ASCII only. No Unicode anywhere in the repo (CRAN requirement): use
  `--` for dashes, `->` for arrows, straight quotes, `...` for ellipses.
  `DESCRIPTION` declares `Encoding: UTF-8`, but keep content ASCII.
  Check with `LC_ALL=C grep -rnP '[^\x00-\x7F]' R/ DESCRIPTION NEWS.md README.Rmd`.

## Release / CRAN

- The package is on CRAN; `cran-comments.md` and `CRAN-SUBMISSION` track
  submissions (both are in `.Rbuildignore`).
- Bump `Version` in `DESCRIPTION` and add the matching `NEWS.md` heading
  before a submission.
- The `.rda` files dominate package size; do not add large datasets
  without asking.
- Any new top-level non-package file must be added to `.Rbuildignore`.
- Do not commit, push, tag, or submit to CRAN unless the user asks.

## CRAN tests: never assert on timing

- Never put a wall-clock timing expectation in a test that can run on CRAN:
  no `expect_lt()`/`expect_true()` on `Sys.time()` differences,
  `system.time()`, `proc.time()`, `bench`/`microbenchmark` results, or any
  other elapsed-time threshold. CRAN check machines are shared and heavily
  loaded, so elapsed time there is random and a timing assertion fails at
  random. Example: nlmixr2plot `test-model-diagram.R` asserted a
  `modelGraph()` call took < 30 s; on CRAN it took 48.4 s and failed.
- Test the result, not the speed. If a speed regression guard is really
  needed, put it only in a test that starts with `skip_on_cran()` (or the
  package's own CRAN skip helper), and never in examples or vignettes.
- Tests that take more than a few seconds should also skip on CRAN.
